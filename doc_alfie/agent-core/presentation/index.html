01

Control policy stays above the provider protocol

A

Invert model transport

The runtime accepts a StreamFn. It does not own a provider catalog, credentials, or a specific model SDK.

B

Keep transcript state explicit

Messages, tools, model choice, reasoning level, partial output, pending tool calls, and errors are observable state.

C

Make control flow inspectable

Turns, messages, and tool phases emit ordered events. Steering, follow-up, stop, and next-turn decisions are named hooks.

D

Separate internal and LLM views

Applications may keep custom messages, then transform and filter them only at the provider-call boundary.

The package orchestrates an agent run without duplicating the provider adapters already owned by pi-ai.

03

Two API levels trade convenience for scheduling control

STATEFUL WRAPPER

new Agent(options)

  • Owns transcript and runtime state
  • Queues steering and follow-up messages
  • Reduces events before notifying listeners
  • Awaits listeners as execution barriers
  • Normalizes thrown loop failures
Best for applications and interactive agents
OR
LOW-LEVEL STREAM

agentLoop()

  • Accepts caller-owned context and callbacks
  • Returns EventStream<AgentEvent>
  • Preserves producer event order
  • Does not await consumer handling
  • Exposes the loop without stored state
Best for custom schedulers and adapters
Use Agent when event handling must complete before the next producer phase; use the loop when observation is enough.

10

Steering and follow-up differ by drain point, not message shape

STEERING

Change direction inside the current run

assistant→tools finish→drain→next model turn

Polled after a completed turn and once at startup. Existing tool calls are not cancelled or skipped.

FOLLOW-UP

Add work after the current task would stop

no tools→no steering→drain→new turn

Polled only after the inner loop exits. It re-enters the run through the outer loop.

Queue modeone-at-a-time drains the oldest messageall injects the entire FIFO batch before one model call

BACKENDPOST /api/stream

PROVIDERSpi-ai runtime

Outbound

Serializes model, context, and safe stream options. Authentication is a proxy bearer token, not a provider key in the browser.

Inbound

Consumes SSE lines. Compact events omit repeated partial messages, so the client reconstructs text, thinking, and tool-call state.

Result

The caller still receives the same AssistantMessageEventStream expected by the agent loop.

streamProxy is an adapter for deployment topology: server-managed auth with unchanged agent behavior.

ARCHITECTURAL TAKEAWAY

Explicit state.
Replaceable edges.

The Agent owns state, queues, cancellation, and awaited application events.

The loop owns turn scheduling, tool batches, and continuation decisions.

StreamFn keeps model transport replaceable without leaking provider logic upward.

AgentMessage lets applications retain richer transcripts than providers understand.

The design turns an LLM stream into a controllable application runtime while keeping every major boundary replaceable.
